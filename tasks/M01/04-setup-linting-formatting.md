# M01.04 — Set up Linting & Formatting

## Objective

Configure ESLint and Prettier for consistent code style, error detection, and automatic formatting across the project.

## Context

The Architecture milestone includes “Configure TypeScript, linting, formatting, environment validation.” This task isolates linting and formatting configuration so they can be validated and run independently. The PRD’s emphasis on quality engineering (Section 3.1) mandates a clean codebase.

## Requirements

- Install development dependencies:
  ```bash
  npm install -D eslint prettier eslint-config-prettier eslint-plugin-prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin
  ```
- Create `.eslintrc.json` that extends `next/core-web-vitals` and integrates `@typescript-eslint` and Prettier. Example:
  ```json
  {
    "extends": [
      "next",
      "next/core-web-vitals",
      "plugin:@typescript-eslint/recommended",
      "prettier"
    ],
    "plugins": ["@typescript-eslint"],
    "parser": "@typescript-eslint/parser",
    "parserOptions": {"project": "./tsconfig.json"},
    "rules": {
      "prettier/prettier": "error",
      "@typescript-eslint/no-unused-vars": ["error", {"argsIgnorePattern": "^_"}]
    }
  }
  ```
- Create `.prettierrc` with a minimal configuration, e.g.:
  ```json
  {
    "singleQuote": true,
    "trailingComma": "es5",
    "printWidth": 100,
    "semi": true
  }
  ```
- Add `.eslintignore` and `.prettierignore` files mirroring the default generated by `create-next-app` (ignore `node_modules/`, `.next/`, `out/`).
- Add npm scripts to `package.json`:
  ```json
  "scripts": {
    "lint": "eslint . --ext .js,.jsx,.ts,.tsx",
    "format": "prettier --write ."
  }
  ```
- Run `npm run lint` to ensure the scaffold passes without errors.
- Run `npm run format` and verify that files are formatted according to Prettier.
- Commit the configuration files and updated `package.json`.

## Scope

### In scope
- Creation and configuration of ESLint and Prettier.
- Adding npm scripts for linting and formatting.

### Out of scope
- Enforcing code style in existing source files beyond the scaffold (those will be addressed in later milestones).
- Integrating custom lint rules beyond the basic set.

## Dependencies

- **M01.02** – The Next.js scaffold must be present.
- **M01.03** – TypeScript configuration should already be in place (the ESLint config references `tsconfig.json`).

## Files / Areas Expected To Change

- `.eslintrc.json`
- `.prettierrc`
- `.eslintignore`
- `.prettierignore`
- `package.json`

## Implementation Guidance

- Keep the ESLint rule set minimal but enforce Prettier formatting.
- Ensure the lint script runs on all source files (including `pages/`, `components/`, `src/`).
- Verify that the lint and format commands exit with code 0 on a clean run.

## Acceptance Criteria

- [ ] ESLint configuration file exists and extends the recommended sets.
- [ ] Prettier configuration file exists.
- [ ] `npm run lint` reports **0 errors** on the scaffolded code.
- [ ] `npm run format` makes no changes when run on a clean codebase.
- [ ] The new scripts are present in `package.json`.
- [ ] All changes are committed.

## Testing Requirements

Run the lint and format scripts locally and ensure they succeed without modifications.
