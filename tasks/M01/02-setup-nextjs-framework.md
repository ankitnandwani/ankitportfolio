# M01.02 — Set up Next.js Framework

## Objective

Bootstrap a Next.js application with TypeScript, ESLint, and Tailwind CSS to serve as the foundation for the portfolio site.

## Context

Milestone 1 (Architecture) requires selecting and configuring the primary framework. The PRD designates Next.js as the frontend stack (see PRD §52). This task satisfies the roadmap entry “Select framework (Next.js).”

## Requirements

- Execute `npx create-next-app@latest . --typescript --eslint --tailwind` (or the equivalent Yarn command) in the repository root.
- Verify that the generated project includes:
  - `package.json` with Next.js, React, React‑DOM, TypeScript, ESLint, and Tailwind CSS dependencies.
  - `tsconfig.json` and `next-env.d.ts` files.
  - `pages/` (or `app/` if using the new App Router) and `styles/` directories.
  - ESLint configuration (`.eslintrc.json`) generated by the scaffold.
  - Tailwind configuration files (`tailwind.config.js`, `postcss.config.js`).
- Ensure the `scripts` section in `package.json` includes `dev`, `build`, `start`, `lint`, and `typecheck` (the latter can be added in a later task).
- Commit the scaffolded files.

## Scope

### In scope

- Generating the Next.js project scaffold.
- Adding the necessary configuration files.
- Initial commit of the scaffold.

### Out of scope

- Adding additional libraries beyond the scaffold (e.g., NeoPOP, Supabase client). Those will be added in later milestones.
- Customizing Tailwind themes beyond the default.

## Dependencies

- **M01.01** – Repository must be initialized before running the scaffold.

## Files / Areas Expected To Change

- `package.json`
- `tsconfig.json`
- `next-env.d.ts`
- `.eslintrc.json`
- `tailwind.config.js`
- `postcss.config.js`
- Various source files under `pages/` or `app/`, `styles/`, etc.

## Implementation Guidance

- Use the latest stable Next.js version (≥ 14 at the time of writing).
- Keep the default TypeScript configuration but ensure `strict` is enabled (this will be reinforced in the TypeScript configuration task).
- After scaffolding, run `npm install` to install dependencies.
- Verify the dev server starts without errors: `npm run dev` should display a localhost URL.

## Acceptance Criteria

- [ ] The Next.js project scaffolding completes without errors.
- [ ] The application starts in development mode (`npm run dev`) and serves the default homepage.
- [ ] `npm run build` succeeds.
- [ ] ESLint runs (`npm run lint`) without any rule violations on the scaffolded code.
- [ ] All scaffolded files are committed to the repository.

## Testing Requirements

- Execute `npm run dev` and confirm the default page loads (HTTP 200).
- Execute `npm run build` and confirm no compilation errors.
- Execute `npm run lint` and confirm a clean lint report.

## Security / Privacy Considerations

No secrets are introduced at this stage. Ensure `.env*` is ignored via `.gitignore`.

## Performance / Accessibility Considerations

The default scaffold follows Next.js best‑practice for performance and accessibility; no additional work is required now.

## Definition of Done

- Implementation is complete.
- All acceptance criteria are satisfied.
- Lint passes.
- Type‑check (via `npm run typecheck` if available) passes.
- No unrelated files were modified.
